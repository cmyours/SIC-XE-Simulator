# SIC/XE Assembler & Simulator

**C로 구현한 SIC/XE 어셈블러·링킹 로더·실행 시뮬레이터**

시스템 프로그래밍 수업에서 진행한 팀 프로젝트입니다. 어셈블리 소스를 오브젝트 코드로 변환하고, 여러 프로그램의 외부 심볼을 연결하여 가상 메모리에 적재한 뒤 명령어를 실행하는 과정을 구현했습니다.

## 주요 기능

| 기능 | 설명 |
| --- | --- |
| 2-pass 어셈블러 | 심볼 테이블 구성 및 `.obj`·`.lst` 파일 생성 |
| 링킹 로더 | 외부 심볼 연결, 주소 재배치 및 Load Map 출력 |
| 가상 메모리 | 1MB 메모리에 프로그램 적재 및 데이터 저장·조회 |
| 메모리 덤프 | 지정한 영역을 HEX와 ASCII로 출력 |
| 실행 시뮬레이터 | 명령어를 Fetch → Decode → Execute 순서로 처리 |
| 브레이크포인트 | 중단 주소 설정·조회·삭제, 실행 중단·재개 및 레지스터 출력 |

SIC/XE 명령어 중 일부를 지원합니다. 어셈블러 출력과 로더 입력 형식 등 현재 구현의 제한은 아래에 명시했습니다.

## 사용 기술

- **언어:** C
- **개념:** SIC/XE 명령어 구조, 주소 지정 방식, 2-pass 어셈블러, 링킹·재배치
- **자료구조:** 명령어 테이블, 심볼 테이블, 외부 심볼 테이블(ESTAB), 메모리 배열
- **실행 확인 환경:** Windows PowerShell, GCC

## 시스템 구성

```text
어셈블리 소스 (.asm)
        ↓
2-pass 어셈블러 → 오브젝트 (.obj) 및 리스트 (.lst) 생성
        ↓
2-pass 링킹 로더 → ESTAB 구성, 메모리 적재 및 주소 재배치
        ↓
1MB 가상 메모리
        ↓
명령어 실행 · 브레이크포인트 · 메모리 조회
```

위 구성은 구현된 각 단계의 역할을 나타냅니다. 현재 어셈블러가 생성한 `.obj`를 바로 로드하는 과정에는 레코드 형식 불일치가 있습니다. 로더 실행 예시는 제공된 `proga.obj`, `progb.obj`, `progc.obj`를 사용합니다.

## 프로젝트 파일

| 파일 | 역할 |
| --- | --- |
| `test.c` | 어셈블러·로더·시뮬레이터 및 메인 명령 처리 |
| `sicsim.h` | 구조체·상수·함수 선언 |
| `opcode.txt` | 명령어 이름·opcode·포맷 정보 |
| `proga.obj`, `progb.obj`, `progc.obj` | 연결·재배치 확인용 오브젝트 파일 |

현재 `test.c`에는 선언이 직접 포함되어 있으며 `sicsim.h`를 포함하지 않습니다. `.obj` 파일은 이 프로젝트에서 필요한 텍스트 형식의 입력 데이터입니다.

## 실행 방법

GCC가 설치된 환경에서 프로젝트 폴더를 열고 컴파일합니다. 아래 명령은 Windows PowerShell 기준입니다.

```powershell
gcc test.c -o sicsim.exe
.\sicsim.exe
```

`sicsim>` 프롬프트에 다음 명령을 한 줄씩 입력합니다.

```text
help
progaddr 4000
loader proga.obj progb.obj progc.obj
dump 4020 402F
bp 4027
bp 402A
bp
run
run
bp clear
quit
```

어셈블러는 `assemble` 입력 후 opcode 파일 이름과 소스 파일 이름을 차례대로 입력하여 사용합니다. 예를 들어 `opcode.txt`, `sample.asm`을 지정하면 `sample.obj`, `sample.lst`를 생성합니다. 별도의 `.asm` 소스는 제공되지 않으므로 직접 준비해야 합니다.

## 실행 결과

### 1. 프로그램 적재 및 외부 심볼 연결

`progaddr 4000`을 입력하면 프로그램을 메모리에 적재할 시작 주소가 0x4000으로 설정됩니다. 이후 `loader proga.obj progb.obj progc.obj`를 입력해 세 개의 오브젝트 파일을 지정한 순서대로 적재합니다.

로더는 먼저 각 파일의 H(Header) 레코드에서 프로그램 이름과 길이를 읽습니다. PROGA의 길이는 0x63이므로 0x4000부터 배치하고, 다음 프로그램인 PROGB는 0x4063부터 배치합니다. PROGC까지 합하면 전체 길이는 0x133이며, 적재 영역은 0x4000부터 0x4132까지입니다.

또한 외부 심볼 테이블에 각 심볼의 실제 주소를 등록하고, M(Modification) 레코드에 따라 참조 위치의 값을 수정합니다. 예를 들어 PROGB의 `LISTB`는 상대주소가 0x60이므로 실제 주소는 0x4063 + 0x60 = 0x40C3입니다.

| 제어 섹션 | 적재 주소 | 길이 |
| --- | ---: | ---: |
| PROGA | 004000 | 000063 |
| PROGB | 004063 | 00007F |
| PROGC | 0040E2 | 000051 |
| 전체 | 004000~004132 | 000133 |

### 2. 메모리 조회 및 재배치 결과 확인

`dump` 명령어로 원하는 범위의 메모리 내용을 조회할 수 있습니다. `dump 4020 402F`를 입력하면 0x4020부터 0x402F까지의 메모리 내용이 HEX와 ASCII 형태로 출력됩니다.

이 구간에서는 외부 심볼 `LISTB`의 실제 주소 0x40C3에 변위 4가 더해져, 명령어의 주소 필드에 0x40C7이 반영된 것을 확인할 수 있습니다. 해당 명령어는 적재 전 `77100004`에서 재배치 후 `771040C7`로 변경됩니다.

```text
sicsim> dump 4020 402F
Memory Dump from 004020 to 00402F:
004020  03201D77 1040C705 0014.... ........  . .w.@..........
```

### 3. 브레이크포인트

지정한 주소에 브레이크포인트를 설정하고, 해당 명령어를 실행하기 직전에 중단하여 레지스터 상태를 확인할 수 있습니다. 중단 후 `run`을 다시 입력하면 실행을 재개합니다.

프로그램의 적재 시작 주소는 0x4000이지만, `proga.obj`의 E(End) 레코드 `E 000020`에 따라 첫 실행 주소는 0x4000 + 0x20 = 0x4020입니다.

`bp 4027` → `bp 402A` → `run` → `run` 순서로 입력하면, 첫 번째 `run`에서는 PC가 0x4027인 상태에서 해당 위치의 `LDX #20` 명령을 실행하기 전에 중단됩니다.

다시 `run`을 입력하면 `LDX #20` 명령을 실행해 X 레지스터에 20(16진수 0x14)을 저장한 뒤, 다음 브레이크포인트인 0x402A에서 중단됩니다.

| 실행 단계 | PC | X 레지스터 |
| --- | --- | --- |
| 첫 번째 중단 | 0x4027 | 0x00 |
| 재개 후 두 번째 중단 | 0x402A | 0x14 |

### 브레이크포인트 재개 처리 개선

기존 구현에서는 중단 시 PC를 미리 증가시켜 재개할 때 해당 명령어를 건너뛰는 문제가 있었습니다. 중단 시 PC를 유지하고, 중단 상태를 저장하여 재개 직후에는 같은 위치의 브레이크포인트 검사를 한 번만 생략하도록 변경했습니다.

수정 후에는 위 예제에서 X가 0에서 0x14로 변경된 상태로 다음 중단점에 도달하는 것을 확인했습니다. 이 결과는 해당 시험 사례에 대한 확인이며, 전체 명령어 집합의 정확성을 검증한 것은 아닙니다.

## 알려진 제한 사항

- 어셈블러가 생성한 공백 없는 레코드를 로더가 정상적으로 읽지 못합니다.
- 포맷 4 즉시값에 적재 시작 주소가 더해지는 문제가 있습니다.
- 포맷 3 즉시값 `2048`이 음수로 해석되는 문제가 있습니다.
- 실행 중 새로 저장한 영역은 `status_map`이 갱신되지 않아 dump에서 가려질 수 있습니다.
- 일부 명령어는 실행 처리가 없으며, `TD/RD/WD`는 실제 장치 입출력을 수행하지 않습니다.
- 도움말의 `reset`, `opclist`는 구현되어 있지 않습니다.

## 학습 내용

어셈블리 소스의 오브젝트 코드 변환, 외부 심볼 연결과 주소 재배치, 가상 메모리에서의 명령어 실행 과정을 구현했습니다. 명령어의 비트 필드와 레지스터·메모리 변화를 다루면서 주소 지정 방식과 실행 흐름을 이해했습니다.

예상 메모리 값과 레지스터 값을 실제 출력과 비교하여 구현 범위를 확인했으며, 브레이크포인트 재개 과정에서 발견한 명령어 누락 문제를 개선했습니다.
